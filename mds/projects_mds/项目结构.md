# 项目结构

项目根 `LoveWorldAgent/`，Tauri/Rust 后端、Vue 前端、CEF sidecar 与数据目录分层；前端只经 `/api` 消费数据。

## 职责边界

1. 前端不拼路径、不写文件；项目路径只在 `config.rs` 计算与写入。
2. Rust 不生成 HTML；页面由 Vite 构建到 `webdist`，由 axum `ServeDir` 托管。
3. 静态资源与日志收敛在 `src-tauri/static`；运行期可写目录开发态为 `src-tauri/static`、打包态为 exe 同级 `static`（`config.rs` 的 `app_dir()`/`writable_static_dir()`）。
4. 规则目录是唯一事实源；权限组定义以 `agent_permission.json` 的 `groups` 为准；会话数据只经 `store_sqls` 进出。
5. 无 `stores/`；状态归属页面组件，请求集中在 `api/`。

## 子项目结构

### ai_browser

```
ai_browser/
├─ CMakeLists.txt          # 单目标构建（GLOB_RECURSE src/*.cpp）
├─ build.ps1               # VS 环境 + CMake/Ninja 一键构建
├─ third_party/cef/        # CEF 111 发行包（需自行解压，不入库）
├─ resources/              # qss、图标、rc（窗口图标）
└─ src/
   ├─ main.cpp             # DPI → CEF 初始化 → 窗口 → 消息泵 → 管道 → 日志
   ├─ components/          # 12 个 bcb_* 自绘控件（lower_snake）
   ├─ uis/                 # qt_app_window / tab_manager / ui_chrome / cursor_overlay / qt_theme
   ├─ server/              # pipe_client / app_handler / cdp_client / agent_api / client_app
   ├─ browser_tool/        # 19 个 browser_*.cpp + tool_registry + tool_helpers
   └─ utils/               # logging / json_util / js_builder / config
```

产物：`out/Release/browser_panel.exe`，CEF 运行期文件与 Qt DLL 由构建脚本部署到同目录。

### ai_computer_use

```
ai_computer_use/
├─ Cargo.toml          # 独立 crate（windows + tokio + clap + image + ort/cuda/load-dynamic + tokenizers + ndarray）
├─ build.ps1           # cargo build --release，拷贝 exe/models/cuda_runtime 到 src-tauri/static/computer_use/
├─ omni_parser/
│  ├─ core/            # lib / parser / detector / ocr / caption / annotator / geometry / bbox / ort_util / server
│  ├─ cuda_runtime/    # onnxruntime.dll、CUDA provider、cudnn/cublas/cudart/cufft（随包）
│  └─ models/          # ocr（PP-OCRv4 det/rec + ppocr_keys_v1）与 ms_vision（icon_detect/tokenizer/源模型）
└─ src/
   ├─ main.rs          # 子命令：pipe --pipe=<name>（23 工具）；omni serve/parse（屏幕解析）
   ├─ config.rs        # 根目录探测 + logging.dir/max_lines + LOG_DIR/LOG_LEVEL
   ├─ logger.rs        # computer_use.log、中文行格式、old_N_ 归档、stderr 同步
   ├─ omni.rs          # 桥接 omni_parser/core，模型目录探测（exe 旁 models 优先）
   ├─ server/          # mod / agent_api(23 工具) / pipe_client(管道)
   ├─ sys/             # screen（截图与自动截图落 static/data/computer_screen）/ overlay（覆盖层）
   └─ uia/             # worker(MTA 线程) / element / tree / finder / snapshot / event / input / desktop / point
```

数据流：命名管道 → `pipe_client` → `agent_api::call` → `uia`（COM 专用线程）或 `sys/screen.rs` → JSON 响应（含顶层可选 `screenshot` 供面板展示，入模型前剥离）；`omni serve` 走 stdio 逐行 JSON → `OmniParser`（CUDA ONNX 会话）→ 元素列表 + over_imgs 标注图。
