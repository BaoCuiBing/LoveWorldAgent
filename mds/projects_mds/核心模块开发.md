# 核心模块开发

按「入口 → 路由 → 日志 → 前端 → 智能体 → 打包」说明职责与扩展点。

## 1. 入口与配置

| 文件 | 职责 |
| --- | --- |
| `src-tauri/src/main.rs` | 仅 `loveworldagent::run()`；`windows_subsystem="windows"` 仅在 release 生效 |
| `src-tauri/src/lib.rs` | `--dev/--debug` 解析 → `config::init()` → `logger::init()` → `app::start_server()` → 选 URL（dev 取 `DEV_SERVER_URL`，生产 `http://{HTTP_HOST}:{HTTP_PORT}/`）→ 图标 → `tauri::Builder` 注册 dialog/notification/opener，`setup` 中建 `main` 窗口（标题/尺寸/背景/居中/DevTools）、写入状态句柄、启终端回收线程、应用标题栏与原生菜单；`CloseRequested` 时停终端与浏览器后 `exit(0)` |
| `src-tauri/src/config.rs` | 路径锚点（`app_dir`/`resource_dir`/`WEB_DIST_DIR`/`STATIC_DIR`/`.loveword`）、默认配置与分层合并、`ensure_agent_files()` 幂等迁移、`project_path()` 每次读盘、`save_project_path()` 校验目录并原子写 |
| `src-tauri/src/api.rs` | Tauri 原生能力：`pick_folder`（`dialog().file().blocking_pick_folder()`）、`notify`（通知插件）、`runtime_info`、`log` |

## 2. HTTP 与路由

`app::router()` 用 axum 装配：`/api/health` + `api::router()` + `rouer::register()`，`fallback_service` 指向 `webdist`（`ServeDir` + `index.html` 回退），并挂全放行 CORS。`start_server()` 起 `http-server` 线程，内部建 tokio 多线程运行时并 `axum::serve`。逐条接口见 `路由接口文档.md`。

| 分组 | 路径 | 说明 |
| --- | --- | --- |
| relus / skill / agent | `/api/relus`、`/api/skills`、`/api/agents` | CRUD、启停、搜索；agent 另有单条读取与 `/api/agent/settings` |
| app | `/api/app/*` | Tauri 目录选择、通知、运行环境、前端日志 |
| permission | `/api/permission` | 读写权限 JSON；GET 附 `groups_meta` |
| project | `/api/project/*` | 目录、单层列表、文本读写、raw、entry、copy |
| chat | `/api/chat/*` | 设置、提示音、SSE、approve、compress |
| session | `/api/sessions/*` | 会话、消息、turns、累计用量 |
| system / model / mcp / upload | 各自前缀 | 主题布局、模型、MCP、附件 |
| terminal | `/api/terminal/*` | portable-pty；WS 为主通道 |
| browser | `/api/browser/*` | sidecar 启停、工具、步骤、截图、Cookie 导入 |
| computer-use | `/api/computer-use` | 电脑控制总开关、自动截图设置、运行态、增量步骤与截图读取/清空；关闭时结束 sidecar、锁定 `computer-control` 技能并停用 `computeruse-agent` |

统一响应 `{code,msg,data}`（`state::ok/fail`）；配置写盘走 `config::atomic_write_json()`（临时文件 + `rename`），按段合并、固定写可写副本。

## 3. 日志

`src-tauri/src/utils/logger.rs`：控制台 + 单文件 `logs/app.log`，行格式 `YYYY-MM-DD HH:mm:ss [LEVEL] 模块: 消息`；超过 `logging.max_lines`（默认 30000）归档为 `old_<n>_app.log` 并重建。级别由 `LOG_LEVEL` 或 `app.log_level` 控制，目录优先级为 `LOG_DIR` → `logging.dir` → `app_dir/static/logs`。敏感字段在业务层脱敏（模型 `api_key` 显示 `前3****后4`，MCP `env/headers` 显示 `****`），业务错误只记单行。

## 5. 前端流程（要点）

```text
启动：InitState 轮询 /api/health → 发 kernel-ready → Chat 加载完派 lwa:app-ready 淡出销毁
      读布局 → GET /api/project → GET /api/sessions → 选中有会话则按 seq 回放 messages
会话：新建=草稿 → 首条消息 POST /api/chat/stream（后端建会话并落 user 消息）
撤回：DELETE /api/sessions/<id>/messages/<turn_key>?after=1 → 同事务清消息与孤儿用量 → 刷新不回弹
发送：未选项目时置灰 + 后端拦截；AppState::active_tasks 互斥锁（流式/压缩冲突 409）
  → SSE 直出 goose AgentEvent：message/usage/messageUsage/mcpNotification/historyReplaced
  → message 分片按 id 合并，content[] 经 goosePart.js 转 text/thinking/tool/confirmation/question/compaction
  → 工具卡按 `PartNode` 平铺，直接 `browser_*`/`computer_*`/`word_*` 各成单卡，子智能体按 callId 归入 SubAgents；未知工具走 `UnsupportedCard`
  → usage/messageUsage 刷新用量；AgencyList 按 InputMessage 选中模型上下文计算进度条百分比；流结束 PATCH 会话状态
压缩：点「压缩」→ POST /api/chat/compress SSE 流式输出 思考过程 → 开始提示 → CompactionCard（含 operations.context.compacted 落库）→ 完成提示，底部显示「✓ 任务完成 | ○ X%」
审批：actionRequired(toolConfirmation) 拿 run_id → approve → stream{resume} 续流
右栏-文件：GET files（单层）→ 展开时按 rel 懒加载 → GET file → 可编辑；Ctrl+S 保存
右栏-终端：WS 首帧 init → open → data/exit；上行 input/resize/close；断线退避重连
右栏-内置工具：BuildPanel 统一展示 Browser/ComputerUse/OfficeOption/Mobile 步进流与自动截图
插入：`#File:`/`#Folder:` 路径、`#`/`/`/`@` 面板；附件 POST /api/upload
```

## 6. 智能体

`src-tauri/src/agent/` 为纯 Rust 实现，`POST /api/chat/stream` 由 goose 状态机（`agent_core/state_machine.rs`）装配并直出 `AgentEvent`。

| 模块 | 职责 |
| --- | --- |
| `settings.rs` | `AgentSettings` 每次读盘 agent 段；播种 relus/skills/agents |
| `rules.rs` / `skills.rs` | frontmatter、CRUD、注入、播种；锁定技能 `sync_locked` |
| `agents_repo.rs` | AGENT.md 仓库、`GLOBAL_PROMPT`、`PROVIDER_PATCHES`、`seed_agents` |
| `agent_core/assistant.rs` | `build_instructions`（按 ask/todo/skill/browser/computer/ppt/excel 开关拼纪律）、规则/技能/摘要注入、主/子 Agent 装配、`agent_list`/`agent_call` |
| `model_support/*` | OpenAI 兼容（`openapi.rs`）与华为云 MaaS V2（`huawei_maas.rs`：`openpangu`/`glm-5.x`/`deepseek-v4.1` 思考开关、effort 与上下文限额归一）适配 |
| `tools_details/*` | 规则/技能/文件/命令/终端/浏览器（21 工具）/电脑（23 `computer_*`）/Office（32 工具）/移动端（28 `mobile_*`）/提问/待办工具；`tools.rs` 薄门面 |
| `permission.rs` | 权限归一、审批判定、理由（8 组与组级硬拦截） |
| `agent_core/state_machine.rs` | 状态机装配：`Approval → PromptParts(assistant) → ToolOperation → UnhandledToolCalls → MaxTurns → InferenceRunner → ExitOnError`；`stream_chat`/`run_task` 与 RAII 任务锁 |
| `agent_core/goose_session.rs` | `GooseSession`/`SessionStore`：`Message`/`Conversation` 读写 SQLite、分片合并、待决审批与用量效果 |
| `agent_core/goose_tools.rs` | `ToolDef` → goose `ToolProvider`/`ToolOperation` 适配与工具路由 |
| `agent_core/goose_approval.rs` | `ToolApproval`（Allow/Deny/Ask）、`ApprovalGate` 包装（组级拦截 Deny 优先） |
| `agent_core/context.rs` | `goose-context-management` 摘要与事实提取、`compress_stream` 流式压缩与 `build_compaction_message` |
| `store_sqls/*` | SQLite 会话/消息/turns/用量/上下文；`db.rs` 建表、旧库备份与行映射；`messages::delete_turn` 回滚消息与孤儿用量 |

关键约定：
- 主智能体全量工具；子智能体按 AGENT.md 的 tools 子集（`rule/skill/file/command/browser/computer/word/ppt/excel/mobile`，空=全部基础工具）。
- 子智能体事件：`agent_call` 生成 callId，`run_task` 消费子智能体 `AgentEvent`，全部消息写 `metadata.operations.subagent{callId,agentId,agentName,seq}`、`userVisible=true`、`agentVisible=false` 后落主会话并实时 SSE；前端 SubAgents 以 agent_call 为卡片主体统一渲染（头部 agentName+状态+N步，卡内消息按 PartNode 正常渲染）。
- 子智能体审批：`ApprovalGate` Ask 走阻塞桥，发 actionRequired 后等待；`/api/chat/approve` 先 `resolve_subagent`，命中返回 `{subagent:true}`，不恢复主会话。
- 全局提示词 = 通用底座 + 模型补丁；工具纪律按对话开关拼入提问/待办/浏览器/电脑条目，技能全关时移除「可用技能」整段。
- 电脑控制 23 个 `computer_*` 归入 `computer` 组；组关闭时 `permission::tool_blocked` 直接拒绝，审批门 Deny 优先于 Ask/Allow；桌面/Office 自动截图路径经由管道帧与 `/steps` 供面板使用，进 LLM 前由 `strip_screenshot_fields` 剥离。
- MCP 启动后由 `mcp::spawn_startup_connect()` 后台常驻连接已启用服务；`browser-automation`/`computer-control`/`word-control`/`ppt-control`/`excel-control`/`mobile-control` 为锁定技能，启动时 `sync_locked` 与开关同步，手工改动被拒。
- 工具参数 Schema 由 `tools.rs` 的 `params`/`schema_of` 生成，支持 `string/integer/number/boolean/string_array/integer_array/number_array`。
- 命令免审批 = 组 enabled AND 条目 enabled；`terminal_send` 走同一审批链，终端工具共 4 个（`terminal_open/send/read/list`）。
- 审批由 `Approval` 步骤写 `actionRequired`，`POST /api/chat/approve` 写 `toolConfirmationResponse`，`stream{resume}` 续流；待决项存 `messages`，进程重启仍可读。
- `max_turns` 默认 200；用量经 `usage`/`messageUsage` 事件下发，`Message.metadata.usage` 回放。

## 7. 打包

`tauri.conf.json`：`productName=LoveWorldAgent`、`identifier=com.loveworld.agent`、`frontendDist=../webdist`，`bundle.targets=["nsis"]`，`resources` 为 `../webdist → webdist` 与 `static → static`，图标取 `icons/`。执行 `cargo tauri build` 产出 `target/release/bundle/nsis/` 安装包。

- 打包态 `RESOURCE_DIR` 优先取 exe 同级 `resources`（不存在则 exe 同级），`APP_DIR` 取 exe 同级；可写内容固定到 `APP_DIR/static/*`。
- 首启由 `config::ensure_agent_files()` 播种并按需生成 `agent_config.json`、`agent_permission.json`、`agent_mcp.json`。
- CEF sidecar 不随 Tauri resources 打包，需手工放到 exe 同级 `browser/`（`utils/browser.rs` 的冻结态路径）。
- computer_use sidecar 随 `static/computer_use` 打包播种：开发态用 `ai_computer_use/target/release/computer_use.exe`，打包态复制到 `APP_DIR/computer_use/`，首次调用由 `utils/computer_use.rs` 拉起 `pipe --pipe=loveworld_computer_use`；`build.ps1` 另把 `omni_parser/models/{ocr,ms_vision}` 复制到 `static/computer_use/models`、`omni_parser/cuda_runtime` 复制到 `static/computer_use/cuda_runtime`（`omni` 运行时优先 exe 旁 `models`/`cuda_runtime`，主应用播种当前只复制 exe）。
- office_option / mobile_use sidecar 同理：分别随 `static/office_option`、`static/mobile` 播种，`utils/office_option.rs` 与 `utils/mobile.rs` 在首次调用时拉起 `pipe --pipe=loveworld_office_option|loveworld_mobile`；移动端 adb 由 sidecar 自行解析 `static/mobile/platform-tools` 或环境变量。

## 8. 整洁度与限制

- `src-tauri/src/rouer/` 目录名拼写遗留，新增路由沿用。
- Rust 代码不写空行，注释统一放在行尾用中文说明；模块首行注释写职责。
- 前端 `.js` 与 `.vue` `<script>` 段去除多余空行（保留多行模板字面量内部空白）。
- `ai_browser/src/qt` 已并入 `src/uis`；「更多」菜单 5 项；图标统一 `resources/icons/`。
- 配置写盘后进程内 `CONFIG`/`AGENT_CONFIG` 等 `Lazy` 不刷新，改模型需重启；权限每次读盘。
- WebView2 与 CEF/Chromium 运行期目录收拢在 `writable_static_dir()/additional/{webview,cache,browser_cache}`，`browser_panel.exe` 传 `--cache` 与 `--root-cache` 指向 `additional/cache`，避免污染根目录。
- 未决审批存于 `messages`（`actionRequired`），无内存 TTL；会话被删或消息为空时 `resume` 报「审批已失效」。
- goose 依赖锁 `=0.1.0-alpha.13`，`goose-providers` 必须保留 `native-tls`。
- 无硬黑名单与沙箱。
- sidecar 关闭标签已改为「先移除 UI 标签再 `CloseBrowser(true)`」并加 1.5s 看门狗。

## 9. 子项目核心模块

### ai_browser

启动链：`main.cpp` → DPI 感知 → Qt 应用 → `CefExecuteProcess` → `logging::Init()` → 解析 `--pipe/--url/--rect/--cache/--root-cache/--settings` → `CefInitialize` → `QtAppWindow::Create()` → QTimer 泵消息 → `PipeClient::Start` → 首个标签。

管道协议 v2：入站 `{"type":"req","id":N,"cmd":"browser_click","args":{...}}`；出站 `res`/`ev`；长文本按 `chunks/chunk/data` 分片；读线程 `PeekNamedPipe` 轮询。

新增工具：`browser_tool/` 新建 `browser_xxx.h/.cpp` 实现 `IBrowserTool` → `tool_registry.cpp` 注册 → `tool::Reply/ReplyOk/ReplyText/ReplyError` 回包 → 需要时同步主应用 `browser_tools.rs` 与 `permission.rs`。

日志：`LOG_INFO("tool", QStringLiteral(...))`，中文正文，默认 INFO（读 `app.log_level`），归档 `old_N_browser_panel.log`。

### ai_computer_use

新增/调整工具：`server/agent_api.rs` 的 `definitions()` 增加 `computer_*` → `dispatch_inner()` 增加同名分支 → UIA 能力走 `uia`、截图走 `sys/screen.rs` → 同步主应用 `computer_use_tools.rs` 的 `spec_defs()` 与 `permission.rs#COMPUTER_TOOLS`。

结构与工具分组：`server/{mod,agent_api,pipe_client}.rs` 定义并分派 23 个 `computer_*` 工具，入口为 `pipe --pipe=<name>`（内置工具，非外置 MCP）与 `omni serve/parse`（OmniParser 屏幕解析）；`uia/`（worker 专用 MTA 线程、desktop/tree/element/finder/snapshot/event/input/point）承载语义定位与交互，`sys/screen.rs` 负责截图；`omni_parser/core` 经 `src/omni.rs` 桥接，模型在 `omni_parser/models/{ocr,ms_vision}`、运行时优先 exe 旁 `models`；随包 `auto_screenshot` 捕获屏幕到 `static/data/computer_screen` 供前端面板展示。

管道协议：`{"type":"req","id":N,"cmd":"computer_click","args":{...}}` → `{"type":"res","id":N,"ok":true,"data":{...},"screenshot?":"..."}`；超过 8000 字节按 `chunks/chunk/data` 分片；连接失败每 500ms 重连。

日志与配置：`config::runtime()` 一次性解析根目录与 `logging`；`logging.dir` 空→`static/logs`；`LOG_DIR`/`LOG_LEVEL` 优先；`pipe` 与 `omni` 日志同落 `computer_use.log`。

### ai_office_option

- 结构：`src/{word,ppt,excel}` 三族工具 + `src/common/{sta,session,registry,progid,paths,backup,report,screen}` 共享层 + `src/com/{dispatch,document,app,constants}` 晚绑定层 + `src/server/{agent_api,pipe_client}` 协议层 + `src/tools/*` 工具注册层；入口 `config.rs`/`logger.rs`/`main.rs`。
- 工具：Word 12、PPT 10、Excel 10，共 32 个；`tools/mod.rs` 判定白名单，`pipe_client` 按前缀路由到 `word::run`、`ppt::run`、`excel::run`，并根据请求携带的 `auto_screenshot` 触发 `common/screen.rs` Win32 可见窗口截图至 `static/data/office_screen`（附于响应顶层 `screenshot` 字段）。
- STA：Word 用 `word/mod.rs` 内单 STA 会话；PPT/Excel 用 `common/sta.rs` 的 `StaCell` 各起一条独立 STA，超时/忙返回 `TIMEOUT`/`APP_BUSY`。
- COM：`com/dispatch.rs` 提供 `get/set/call`、ProgID 参数化（`app_clsid/create_app/attach_app`）、`Variant` JSON 桥、`APP_NOT_INSTALLED`/`APP_GONE` 映射。
- 路径/备份/信封：`Paths` 允许本机合法路径，仅拒绝 UNC/设备路径与 `..` 穿越；保存前 `.bak` 轮转；成功/失败统一 `{ok,data,error}` 信封。
- 新增工具：在对应 `ppt/*.rs` 或 `excel/*.rs` 增加 `run()` 分支 → `ppt/mod.rs`/`excel/mod.rs` 白名单与 timeout → 主应用 `office_tools.rs` 与 `permission.rs` 同步。

### frontend

对话流：`InputMessage` → `Chat.vue#send` → `POST /api/chat/stream`（fetch + SSE）→ `chatEventReducer` → `MessageListFather` → `TurnItem` → `AiMessageSee` → `PartNode` → 具体卡片。

停止：运行中红色停止按钮 → 先 `/api/chat/approve`（reject 待决审批）→ `/api/chat/stop` → `AbortController.abort()` → 回合 `cancelled`、会话 `interrupted`。

卡片分工：CommandCall（命令/终端）、DiffChangesCard（file_write）、FileEdit（delete/read/list 不渲染正文）、McpCall、RuleCall（只读）、SkillCall（read/list）、UpdateList、QuestionCard、ConfirmationCard、BuildToolCall（直接 `browser_*`/`computer_*`/`word_*`/`ppt_*`/`excel_*`/`mobile_*` 内置工具统一单卡）、SubAgents（agent_call 子智能体统一卡）、CompactionCard（手动压缩折叠卡）、UnsupportedCard（未知工具兜底，右侧黄色「继续」按钮右对齐）。

右栏联动：DiffChangesCard 文件夹图标 → `Chat.vue#openFileInPanel` → `RightTools#openFile` → `FileCode#openFile` → `FileCodeTree#revealActive`（逐级展开、滚动选中）→ `FileCodeViewer` 激活页签；待办 `AgencyList` 根据当前选中模型计算 token 占用百分比并触发 SSE 压缩。

终端：标签标题固定「终端」，cwd 单独展示；`localStorage` 只存 `activeIndex` 与 `tabs[{cwd}]`；智能体会话（`owned=false`）不持久化、不回收后端 PTY。
