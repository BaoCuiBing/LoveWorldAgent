# 注意事项

## 版本控制

约定忽略：`node_modules/`、`webdist/`、`src-tauri/target/`、`src-tauri/gen/`、`src-tauri/static/{logs,uploads,additional}/`、`ai_browser/{third_party,build,out}/`、`test/scripts/`、`test/temp/`。`src-tauri/static/.loveword/` 需随仓库分发；`data/lwa.db` 未忽略（运行期数据）。

## 路径与加载

1. 必须 hash 路由（`createWebHashHistory`，桌面端无需 history 回退）。
2. `vite.config.js` 必须 `base:'./'` 且 `build.outDir='../webdist'`，否则 `webdist` 内资源 404。
3. 路径锚点只有 `src-tauri/src/config.rs`（对应原 `config.py` 语义），入口必须在 `src-tauri` 下 `cargo run`。
4. 冻结态 `APP_DIR` 取 exe 目录，`RESOURCE_DIR` 优先 exe 同级 `resources/`；可写内容一律在 exe 同级 `static/`。
5. 生产窗口加载 `http://127.0.0.1:8866/`（axum 托管 `webdist`），不再使用 `file://`；页面未构建时窗口空白或 404；启动阶段由 `InitState.vue` 轮询健康检查遮罩避开白屏，收到 `lwa:app-ready` 后淡出销毁。
6. 项目目录由 `config::project_path()` 每次读盘；文件/命令工具 root 即项目目录，未选统一提示「请先选择项目文件夹」。
7. sidecar：开发态 `ai_browser/out/Release/browser_panel.exe`，打包态 exe 同级 `browser/`；CEF/Chromium 缓存统一在 `writable_static_dir()/additional/cache`（开发态 `src-tauri/static/additional/cache`），启动参数带 `--cache` 与 `--root-cache`；`browser_cache` 历史目录亦收纳于 `static/additional/browser_cache`。
8. `src-tauri/static/additional/webview` 为 WebView2 用户数据目录；`lib.rs` 通过 `data_directory` 固定到可写 `additional/webview`，避免系统缓存锁冲突。
9. 配置与 `.loveword` 完全兼容：Rust 版直接读现有 `config.json` 与 `.loveword/*.json`，字段语义不变；缺失的 `agent_config/agent_permission/agent_mcp` 由 `config::ensure_agent_files()` 生成，旧 `config.json` 的 `agent/llm/permission` 段在首次迁移后删除（`MIGRATION_REPORT.stripped`）。

## Rust 代码约定

- 顶层模块在 `lib.rs` 声明；新增路由放 `rouer/`，新增智能体逻辑放 `agent/`，工具实现放 `agent/tools_details/`。
- 智能体编排只改 goose 状态机：新增步骤实现 `Operation<GooseSession, ChatEffect>` 并插入 `state_machine.rs` 的 `steps`；新增工具返回 `ToolDef` 即可，由 `goose_tools.rs` 适配为 `ToolProvider`。
- goose 四件套锁定 `=0.1.0-alpha.13`，`goose-providers` 保留 `native-tls`；不要恢复自研 ReAct/SSE 循环。
- 不写空行，注释一律放行尾并用中文；模块首行注释说明职责（与现有 `main.rs`、`config.rs`、`app.rs` 保持一致）。
- 响应统一 `state::ok/fail` → `{code,msg,data}`；请求体用 `Bytes + body_object` 解析，避免 extractor 抛 400 破坏错误结构。
- 配置写盘只用 `config::atomic_write_json()`（`.tmp` + `rename`），并按段合并，保留同文件其它字段。
- 共享状态只经 `state::shared()` 的 `AppState`：SQLite 单连接加锁、窗口句柄为可选槽位（HTTP 先于窗口就绪）。
- 新增 Tauri 插件需同步 `tauri.conf.json`、`capabilities/default.json` 与 `lib.rs` 的 `Builder`。

## 前端约定

- 纯 JavaScript（`.js` / `<script setup>`），不引入 TypeScript；UI 只用 shadcn-vue（`components/shadcn_ui`）+ Tailwind 原子类，图标用 `lucide-vue-next`。
- 4 空格缩进、无分号、单引号；新增基础组件放 `components/shadcn_ui/ui`，复用 `lib/utils` 的 `cn()`。
- 对话只消费 goose `AgentEvent`（`chatContract.js` 定义类型，`chatEventReducer.js` 合并消息）；不要复活 `assistant/init`、`part/upsert` 等旧帧。
- 主题只由 `theme.js` 改 `html.dark`，持久化 `config.json.ui.theme`。
- 工具失败态由 `toolPart.js` 按 result 文案前缀判定；`goosePart.js` 把 `Message.content[]` 转 parts，后端只发 goose 原始消息。
- 无 `stores/`：状态归页面组件，请求集中在 `api/request_data.js`。
- 历史压缩：`Chat.buildHistory()` 抽取本轮之前的 user/assistant 纯文本，作为 `/stream` 的 `history`（超 80% 自动压缩）与 `/compress` 入参；`resume` 请求不传 history。
- 终态：`finishRun` 按未决审批与 `error` 块决定 paused/failed/completed 并 PATCH 会话状态；启动时 `correctStaleSessions` 校正遗留 `running`。
- 本地存储走 `api/local_storage.js`（`lwa:` 前缀），`getNumber` 空串回退 fallback。
- 三栏宽度：左 200~420（默认 264）、右 420~1000（默认按 `(innerWidth-24)×44%`，保证中栏 ≥480）；拖过后固定像素。
- 右栏用 `v-if` 控制第三栏，分割线随 panel 消失；展开/收起与 resize 用 `:key` 重建分栏，输入草稿全量双向同步。
- 右栏四面板 `v-show` 保活，顺序待办/浏览器/文件/终端；`file_code/` 只留 `FileCodeTree`、`FileCodeViewer`。
- 文件树懒加载：`/api/project/files` 只返回一层，展开时按 `rel` 再请求；禁止改成一次递归到底。
- 文件面板：预览在左、树在右（默认 23%，20%~70%）；右键 6 项菜单；创建同名 409 不改名、粘贴冲突自动 `-copy`。
- 消息：goose `Message.content[]` 分块；`ask_user`/`terminal_open` 等按 `suppressed` 不渲染；一条命令一张卡；`todos` 由 `UpdateList` 渲染。
- 折叠：工具卡平铺，不再聚合 `ToolGroup`，报错时也不折叠前置内容；直接 `browser_*`/`computer_*`/`word_*`/`ppt_*`/`excel_*`/`mobile_*` 统一渲染单卡（`BuildToolCall`），子智能体走 `SubAgents`；未知工具走 `UnsupportedCard`；confirmation/question 交互完成后收起为单行。
- 输入：`#File:`/`#Folder:` 走路径层；`#`/`/` 用 `InsertContext.vue`；`@` 用 `InputMessage.vue`。
- 厂商图标统一 `assets/providers.js#providerIcon` → `assets/model_icons/*.png`；缺失时回退 `Sparkles`。文件类型图标统一 `assets/fileIcons.js`。
- Monaco 0.57：`editor.api.js` 入口，11 语言，worker 按 label 分流。

## 权限与命令审批

- 数据文件 `.loveword/agent_permission.json`，整个文件即权限对象：`mode`（manual/auto/full）、`groups`、`custom`。
- 唯一事实源是文件 `groups`；8 组：`mcp`（按 `agent_mcp.json` 服务生成）、`powershell`（19 条高风险，默认灰）、`browser`（21 条工具，默认蓝）、`computer`（23 个 `computer_*`，默认允许）、`word`（12 项）/`ppt`（10 项）/`excel`（10 项）、`mobile`（28 个 `mobile_*`，默认允许）。前端不硬编码命令组。
- `computer` 组同时是电脑控制总开关：设置-内置工具「电脑」经 `GET/PUT /api/computer-use` 读写开关与 `agent_computer_use.json`（含 `auto_screenshot`）；组关闭时 `tool_blocked` 组级硬拦截（Deny 优先），并结束 sidecar、锁定 `computer-control` 技能、停用 `computeruse-agent`。
- `auto`：未列命令默认放行；仅 powershell 灰条目命中或输出重定向（剔除 `2>&1` 后仍有 `>`）中断。
- 浏览器工具走 `tool_needs_approval("browser", name)`；`custom` 命中工具名免审批。
- 命令的 `custom` 命中同样免审批；但重定向优先于 custom 前缀匹配：仅当 custom 条目自身也含重定向时才放行，避免「echo hi」放行「echo hi > out.txt」。
- MCP 列表 `env/headers` 脱敏为 `****`，编辑提交 `****` 时保留原值；`/json` 整文件模式仍返回真实值。
- 三档：`full` 不审批；`auto` 仅上述项中断；`manual` 每步中断。
- 审批链：goose `Approval` 步骤在 assistant `Message` 写 `actionRequired`（`actionType=toolConfirmation`）→ 状态机暂停 → `POST /api/chat/approve` 写 `toolConfirmationResponse` → `POST /api/chat/stream {resume:会话id}` 续流；`always` 写 custom。
- 待决项存 `messages`，无内存快照与 TTL；会话消息为空（被删/清空）时 `resume` 报「审批已失效」，`approve` 无待决返回 409。
- 子智能体审批：`ApprovalGate` Ask 时发 actionRequired 并阻塞等待（默认 300s）；`/api/chat/approve` 先 `resolve_subagent`，命中返回 `{subagent:true}`，前端不再 `resume` 主会话；超时/取消按拒绝处理。
- 子智能体消息：`metadata.operations.subagent{callId,agentId,agentName,seq}`，`userVisible=true`、`agentVisible=false`；前端按 callId 归入 SubAgents 卡，actionRequired 放对话底部。
- 权限页：8 组手风琴内联在「自动审批」下；徽标可点选、整组开关、custom 可删除；徽标配色用 shadcn-vue/Tailwind 类名控制，不再依赖 Element Plus 变量。

## 智能体

- 内置 `Agent` 为主智能体；自定义均为子智能体；`AgentEdit` 固定 580px。
- 全局提示词 = `GLOBAL_PROMPT` + provider 补丁；`assistant::build_system_prompt` 注入。
- 运行参数 `agent` 段：`max_turns` 默认 200、两个超时；`AgentSettings` 每次读盘。
- 编排：`state_machine.rs` 按 `Approval → PromptParts → ToolOperation → UnhandledToolCalls → MaxTurns → InferenceRunner → ExitOnError` 装配；子智能体走 `run_task`（内存会话，不落库）。
- token：`usage`/`messageUsage` 事件带真实用量，并写入 `session_usage` 与 `Message.metadata.usage`；上游不返回 usage 时按 0 处理。
- 目录 `agents/<id>/AGENT.md`；id 小写字母开头 2-50 位；tools 子集 `rule/skill/file/command/browser/computer/word/ppt/excel/mobile`（空=全部基础工具）。
- 随包骨架：`browser-agent`（tools=browser）、`computeruse-agent`（tools=computer，随电脑控制开关启停）、`worduse-agent`/`pptuse-agent`/`exceluse-agent`、`mobileuse-agent`（tools=mobile，随移动端开关启停）；`seed_agents` 首次复制到可写目录，不覆盖用户改动。
- 电脑控制 23 个 `computer_*` 工具；开关关闭时组级拦截优先。
- 终端工具 4 个：`terminal_open/send/read/list`；只在 `terminal_send` 审批；会话回收交 `terminal_router`。
- 工具执行：内建工具经 `goose_tools.rs` 适配 `ToolProvider`，审批门为 `goose_approval.rs`；外部 MCP 由 `agent/mcp.rs` 连接，启动后 `spawn_startup_connect()` 后台常驻连接已启用服务。
- 薄门面勿删：`agent/tools.rs` 仅 re-export `tools_details` 的 `build_*`，新增工具加到子模块并让门面同步。

## 会话与消息

- SQLite `data/lwa.db`：`sessions`、`messages`（`data` 列存 goose `Message` JSON，`UNIQUE(session_id,seq)`）、`turns`（`UNIQUE(session_id,seq)`）、`session_usage`、`session_context`、`context_facts`。
- 旧结构库（`messages` 无 `data` 列）首次启动自动备份为 `lwa.db.bak` 并重建空库，同时清理 `-wal`/`-shm`。
- 状态 `running/completed/interrupted/failed`；列表按 `updated_at` 倒序；删除会话连同消息。
- 落库由后端驱动：`/stream` 写入 user 消息，assistant 消息随状态机效果写入（同 id 的 text/thinking 分片合并）；前端只读取回放。
- `GET /api/sessions/<id>/messages` 返回 `{id,session_id,seq,role,message,created_at}`，`message` 为完整 goose `Message`。
- `sessions.project_path` 已建但未写入/未过滤，未做跨项目隔离。
- 清库：菜单「工具 → 清除数据」→ `views/others/ClearData.vue`；`GET /api/data/clear` 返回会话/消息计数与 `running`，`POST /api/data/clear` 单事务清空 `messages/turns/session_usage/session_context/session_compaction/context_facts/sessions` 七表并返回计数，运行中返回 409。

## 项目目录与右栏

- 顶栏「选择文件夹」→ `POST /api/app/pick_folder`（Tauri 目录对话框并写 `project_path`）；也可 `PUT /api/project`；`save_project_path()` 校验目录。
- 文件 API：路径须项目内相对路径；`q` 搜索深度 ≤6、≤500 条；读 ≤200KB、写 ≤1MB；二进制拒绝。
- 终端：一标签一条 WS（`/api/terminal/ws`），首帧 init → open → data/exit；上行 input/resize/close；Vite 必须保留 `ws:true`。
- 终端会话分池：user 12 / agent 4；已退出/空闲 2h/无订阅 120s 回收；`persistent` 跳过回收。
- 浏览器是独立顶层窗口；右栏只做入口，不承载 CEF 视图。
- 标题栏 ✕ 只隐藏（`HideSelf`），进程与管道保活；真正退出仅 `window_quit` 或 `stop()` 的 taskkill。
- 管道两侧必须 `PeekNamedPipe` 轮询；`ConnectNamedPipe` 阻塞，`stop/start` 前必须关闭实例。
- 禁止在 HTTP 请求线程直接操作 sidecar 窗口；显隐/导航一律经管道。
- 启动必须幂等且异步：`start()` 持启动锁，`start_async()` 后台受理并立即返回 accepted，前端轮询 `/state`。
- 模拟鼠标：`CursorOverlay` 为独立顶层透明窗口（`WindowTransparentForInput`），由 Qt UI 线程绘制；`browser_click/hover/type` 回传元素中心坐标与视口尺寸，按比例定位；窗口移动/缩放时同步边界；隐藏窗口时一并收起。
- 已知限制：CEF 111 进程内 CDP 不受理 `Input.dispatch*`，交互用 DOM 事件派发；导航或 DOM 变化后旧 `ref` 失效，需重新 snapshot。
- `browser_tabs close` 回包反映关闭前状态；关闭链路已改为先移除标签再 `CloseBrowser(true)`，实测标签数 2→1。

| 图标不生效 | `icons/` 内 `dragon.ico`、`32x32.png`、`128x128.png`、`icon.png` 齐全且与 `bundle.icon` 一致 |
| 首启技能/智能体为空 | `seed_skills`/`seed_agents` 播种；确认 `.loveword` 随包 |
| 缺 `agent_config.json` | `ensure_agent_files()` 幂等生成 |
| 缺内置浏览器 | 手工放 `browser/`（含 `browser_panel.exe`、`libcef.dll`、pak/locales） |
| 打包后无法连接 8866 | 检查防火墙/端口占用；`HTTP_HOST` 保持 `127.0.0.1` |
| exe 全黑 | 冷启动/改尺寸；`WEBVIEW_DEBUG=1` 取证 |

## 已知限制

1. CEF 首个导航早于管道连接时上报可能丢失，`start` 连上后会补发一次 `navigate`。
2. kimi 流式可能不回 usage；前端仅在 usage 有值才显示消耗 token。
3. `AGENT_CONFIG` 启动时加载，运行中改模型需重启；权限例外。
4. 未决审批存于 `messages`，无 TTL；会话消息被清空/删除后 `resume` 报失效，`approve` 返回 409。
5. 无硬黑名单与沙箱；终端用户标签不经审批。
6. 会话未做跨项目隔离。
7. `ai_browser/{third_party,build,out}` 不入库，需本地解压 CEF 并构建。
8. sidecar 工具条为中文文字；窗口非前台时首次点「更多」不弹。
9. 关闭标签已修：先移除 UI 标签再 `CloseBrowser(true)` 兜底（CEF windowed 下 `OnBeforeClose` 常不回调），实测 2→1。
10. `computer` 组已接入 23 个 `computer_*` 工具（默认允许）；`computer-control` 技能由「内置工具 → 电脑」开关锁定，不随技能页手工修改；桌面自动截图落 `static/data/computer_screen` 并仅用于面板展示。
11. goose 为 `0.1.0-alpha.13` 预发布版，升级需同步四处版本并回归状态机与 AgentEvent。
12. 移动端仅支持 adb 可达的 Android 设备；iOS、云端设备与远程分配不实现；Unicode 输入依赖设备剪贴板能力；配置落 `.loveword/agent_mobile.json`。

## 子项目注意事项

### ai_browser

- 链接失败 `LNK1104` 多为 `browser_panel.exe` 正在运行，先结束进程。
- 新增含中文的 `.cpp` 可能触发 C4819 并被 `/WX` 判错，已统一 `/wd4819`。
- 文件名统一 lower_snake（`bcb_button.h`、`config.h`），类名保持不变；重命名后需清理旧 build 产物。
- `CreateBrowserSync` 在 CEF 消息循环启动前会死锁，必须 `CreateBrowser` + `OnAfterCreated`。
- 浏览器子窗口父级是承载区原生窗口（`HostHwnd`），不是主窗口，否则被 Qt 遮住白屏。
- CEF windowed 下 `OnBeforeClose` 可能不回调：先移除 UI 标签再 `CloseBrowser(true)`，并用看门狗复位抑制标记。
- 关闭窗口（✕）只隐藏保活，`window_quit` 才退出；关闭标签期间的 `WM_CLOSE` 必须忽略。
- `id==0` 为一次性指令不回包；大截图/元素树必须分片；CEF 子进程不要重复初始化日志。
- 独立调试：`& out\Release\browser_panel.exe --url=https://example.com`。

### ai_computer_use

- 独立 crate：验证要单独 `cd ai_computer_use && cargo check`，不随 `src-tauri` 编译。
- 构建并随包：`powershell -ExecutionPolicy Bypass -File ai_computer_use\build.ps1`；exe 拷贝到 `src-tauri/static/computer_use/`，模型拷贝到 `models/{ocr,ms_vision}/`，`omni_parser/cuda_runtime/*.dll` 拷贝到 `cuda_runtime/`（`omni` 优先 exe 旁 `models` 与 `cuda_runtime`，主应用播种只复制 exe）。
- 子命令：`pipe --pipe=<name>`（23 个 `computer_*`）与 `omni serve/parse`（OmniParser）；`icon_detect.onnx` 必需；`ocr/ch_PP-OCRv4_det/rec_infer.onnx` + `ppocr_keys_v1.txt` 缺失时 OCR 自动禁用；`florence2_encoder/decoder.onnx` 缺失时图标描述自动禁用；OCR 为 PP-OCRv4（DB 检测 + CTC 识别，中英数字，batch 16）。
- 自动截图：`auto_screenshot` 默认开启（`.loveword/agent_computer_use.json`），截图仅存 `static/data/computer_screen` 供面板与 `/steps` 展示，绝不进入 LLM 上下文。
- GPU：`ort` 2.0-rc12 以 `cuda + load-dynamic` 加载 ORT 1.30 的 `onnxruntime.dll`；`icon_detect`/`ocr_det`/`ocr_rec` 均使用 CUDA EP；CUDA EP 配置 4GB arena 上限 + HEURISTIC + workspace=0 + SameAsRequested，实测显存峰值 ~1.9GB（增量 ~1.2GB）、GPU 峰值 46%、进程 CPU 约 1 核、每图 ~0.4s；CUDA 运行时 DLL 在 `ai_computer_use/omni_parser/cuda_runtime`，由 `build.ps1` 随包到 `static/computer_use/cuda_runtime`。
- 新增依赖注意 `windows` features，缺 feature 表现为 `unresolved import`。
- UIA 必须在专用线程 `CoInitializeEx(MTA)`，跨线程使用 COM 对象会失败。
- 元素 ID 按 RuntimeId 复用，窗口重建后旧 ID 失效，需重新 `computer_get_app_state`。
- 操作管理员窗口受 UIPI 限制，失败优先提示用户提权，不要反复重试。
- 截图走 BitBlt，受 DPI 缩放、多屏、窗口遮挡影响；受保护窗口可能全黑。
- 输入使用 SendInput，需目标窗口在前台；组合键顺序按下、逆序抬起。
- 协议帧只走命名管道，调试输出必须走 `log_*!` 宏（stderr + 文件）。
- `control_status` 工具已下线；控制权状态不再对外暴露，需要人工判断时直接交还用户。

### ai_office_option

- 独立 crate：`cd ai_office_option && cargo check`，不随 `src-tauri` 编译；输出 bin 为 `office_option.exe`。
- 构建并随包：`powershell -ExecutionPolicy Bypass -File ai_office_option\build.ps1`（拷贝到 `src-tauri/static/office_option/`）。
- 三族共用 `loveworld_office_option` 管道与 `.loveword/agent_office.json`（已移除 `allowDirs` 白名单，允许全部本机合法路径，仅拒 UNC/设备路径与 `..` 穿越；`auto_screenshot.{word,ppt,excel}` 默认皆 `true`）；Word/PPT/Excel 各自独立 STA 线程，互不阻塞。
- 可见窗口自动截图仅捕获可见且非最小化的顶层宿主窗口落 `static/data/office_screen`，通过响应顶层 `screenshot` 字段传递到右栏 `OfficeOptionPanel.vue`，进入 LLM 工具结果前强制剥离。

- 只读文档/演示/工作簿的写入统一返回 `READ_ONLY`；PPT/Excel 的 `Value2` 逐格读写，避免二维 SAFEARRAY 差异。
- 单次调用超时返回 `TIMEOUT`，连续 3 次后受控回收 sidecar；后续请求在 STA 忙时返回 `APP_BUSY`。
- Office 三族设置不再使用旧版分体配置文件，统一归并至 `.loveword/agent_office.json`。

### ai_mobile

- 独立 crate：`cd ai_mobile && cargo check`，不随 `src-tauri` 编译；输出 bin 为 `mobile_use.exe`。
- 构建并随包：`powershell -ExecutionPolicy Bypass -File ai_mobile\build.ps1`（拷贝到 `src-tauri/static/mobile/`）。
- adb 解析顺序：设置 `adbPath` → `ANDROID_HOME`/`ANDROID_SDK_ROOT` 的 `platform-tools` → PATH → `static/mobile/platform-tools`。
- 多设备必须显式指定 `defaultDevice`，否则返回 `DEVICE_REQUIRED`；无授权设备返回 `DEVICE_NOT_FOUND`。
- 截图尺寸可能与物理分辨率不同，点击/滑动坐标按比例换算；`mobile_get_screen_size` 可读真实分辨率。
- 非 ASCII 输入依赖设备剪贴板广播（clipper/ADB Keyboard），失败返回 `UNSUPPORTED_INPUT`，不要反复重试。
- `mobile_set_location` 仅模拟器可用；`uiautomator dump` 在部分页面可能超时，重试一次后放弃。
- 截图/录屏落 `static/data/mobile_screen`，配置落 `.loveword/agent_mobile.json`，日志 `static/logs/mobile_use.log`。

### frontend

- `npm run build` 输出到项目根 `webdist`，改目录要同步 `tauri.conf.json`。
- 开发态两个终端：先 `cargo run -- --dev`（8866），再 `npm run dev`（5173）；8866 被占用会白屏；首屏加载由 `InitState.vue` 轮询健康检查遮罩防白屏。
- 无全局 store，`Chat.vue` 是会话/右栏/流式/选中模型上下文上限的唯一来源；新建会话后立即 `markSession(sid,'running')`，`correctStaleSessions` 必须跳过正在流式的会话；撤回统一走 `DELETE /api/sessions/<id>/messages/<turn_key>?after=1`。
- 右栏未挂载时 `rightToolsRef` 为空，需重试到可用再 `openFile`。
- `md_show` 只面向新契约（`status`/`meta`/`arguments`/`output`/`actionRequired`），不回退 `args`/`result`；不出现自绘 `CodeBlock`；手动压缩渲染 `CompactionCard`，`UnsupportedCard` 的黄色「继续」按钮右对齐。
- 全部 `.js` 与 `.vue` `<script>` 段不留多余空行（多行模板字面量内部空白除外）。
- 提问卡全部必答；运行与压缩期间均以 `active_tasks` 锁定并发（409），运行期显示红色停止按钮；终端 localStorage 不保存 `title`/`nextSeq`。
