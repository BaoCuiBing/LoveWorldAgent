# 规则（Rules）使用指南

规则是以 Markdown 编写的持久化约束，智能体在每次对话开始时读取全部规则并强制遵守。适合沉淀团队规范、项目约定与个人偏好。

## 规则是什么

- 规则 = 一条一条写入 `.md` 文件的约束，智能体每次回答前都会把它当作"最高优先级须知"。
- 规则全局生效：无论在哪个会话提问，规则都会注入系统提示。
- 规则区分于技能：规则是"必须遵守的约束"，技能是"按需查阅的操作手册"。

## 目录结构

```
src-tauri/static/relus/          # 规则可写目录
├── code-style.md              # 一条规则一个文件
├── commit-format.md
└── response-style.md
```

- 文件名即规则名，建议使用小写英文 + 横线。
- 仅支持 `.md` 文件，其它文件会被忽略。

## Frontmatter 字段

每条规则文件顶部可选支持简单前置块：

```markdown
---
alwaysApply: true
description: 提交信息与代码风格约束
---

# 提交规范

1. 提交信息使用中文，一句话说明"为什么"。
2. Python 代码遵循 PEP 8，中文 docstring。
```

| 字段 | 说明 | 默认 |
| --- | --- | --- |
| `alwaysApply` | 是否每次对话都注入；`false` 时仅当描述与任务相关才提示 | `true` |
| `description` | 一句话描述规则用途，便于智能体判断相关性 | 空 |

## 生效方式

1. 应用启动或规则变更后，智能体在下一次对话时重新加载规则全文。
2. 规则正文以"## 规则（必须遵守）"小节注入系统提示。
3. 规则数量建议控制在 30 条以内，单条不超过 20 行，避免挤占上下文。

## 编辑示例

通过界面或 API 新建规则：

```
POST /api/relus
{ "name": "response-style", "content": "# 回复风格\n\n1. 回复使用中文。", "trigger": "", "description": "回复语言约束" }
```

通过对话修改：直接说"把回复风格规则改成永远先给结论"，智能体会先读取原文再写入。

## API 一览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/relus` | 规则列表（名称、大小、更新时间） |
| GET | `/api/relus/<name>` | 读取单条规则正文 |
| POST | `/api/relus` | 新建规则 `{name, content, trigger, description}` |
| PUT | `/api/relus/<name>` | 覆盖规则 `{content, trigger, description}` |
| DELETE | `/api/relus/<name>` | 删除规则 |

## FAQ

**Q：规则和技能有什么区别？**
A：规则每次对话都注入且必须遵守；技能只在系统提示里给出名称与用途，智能体按需读取正文。

**Q：规则太多会怎样？**
A：全部注入会占用上下文，建议合并同类项，把长篇操作步骤改写成技能。

**Q：删除规则能撤销吗？**
A：不能，删除即物理移除文件，请谨慎操作。

**Q：规则支持变量或条件吗？**
A：不支持，规则是纯文本约束，动态逻辑请用技能脚本实现。
